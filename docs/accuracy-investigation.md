# 工地截图识别偏差排查

测试图片：`IMG_2377.PNG`，1206×2622。
人工观察到 4 人：白色、黄色安全帽各 1 人，另外 2 人未戴安全帽。

## 已复现的问题

平台当前模型来自 BikesHelmets 骑行头盔数据，原训练/验证/测试分别为
1483 / 129 / 59 张。骑行头盔与工地安全帽场景不同，这是模型选型的问题。
此前功能测试通过只说明上传、推理、存储和视频播放流程可用，不能证明工地识别准确。

| 条件 | helmet | no_helmet | 实际情况 |
|---|---:|---:|---|
| 完整截图，640，阈值 0.95 | 0 | 0 | 复现用户上传记录中的结果 |
| 完整截图，640，阈值 0.25 | 2 | 0 | 黄色帽正确，底部文字区域误检；白帽和两颗裸头漏检 |
| 完整截图，1280，阈值 0.25 | 1 | 0 | 仍有明显漏检 |
| 仅照片区域，1280，阈值 0.25 | 2 | 1 | 仍漏掉右侧未戴帽头部 |

直接调用 Ultralytics 与平台检测得到相同框；CPU 与 MPS 结果一致。
平台图片读取后的像素与 OpenCV 直接读取一致，类别映射也正确。
另一份来自同一骑行数据集的旧权重同样不适合这张工地图。
诊断产物位于忽略目录 `test-artifacts/accuracy/`，没有改写用户上传或检测记录。

## 已修正的界面说明

置信度阈值是过滤低分预测框的门槛，**不是准确率百分比**。
0.95 会过滤掉很多真实目标。界面提供回到 0.25 的按钮和高阈值提示，
并注明当前权重的骑行训练场景。零目标不代表图片里没有人或安全帽。
模型说明通过 SHA-256 与权重绑定，替换权重后旧说明不会继续错误显示。

这类提示不会修复模型本身；默认权重仍需用匹配场景的数据重新训练并评估。
根据用户要求，已改为准备 SHWD 数据和手动训练流程，见 [训练指南](training.md)。
用户这张图片不加入训练、验证或测试集，留作训练后的独立人工对照。

参考：[Ultralytics 推理参数](https://docs.ultralytics.com/modes/predict/)、
[官方 SHWD 数据说明](https://github.com/njvisionpower/Safety-Helmet-Wearing-Dataset)。
